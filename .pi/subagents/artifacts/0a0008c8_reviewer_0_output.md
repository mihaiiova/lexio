## Review
- Blocker: Storage failures are silently treated as successes. `lib/progress/user_progress.dart:188-192` catches and discards every write error, so `recordAnswer()`/`recordAnswers()` resolve successfully even when persistence failed. This does not make failure “**explicit/no uncaught async**.” Return a non-throwing failure result (or otherwise report it) and add an assertion in `test/progress/progress_repository_test.dart:43-57` that callers can detect it while in-memory progress remains intact.

- Note: The app still has no completion/flush handling for its ignored persistence futures (`grammar_screen.dart:84-88`, `idioms_screen.dart:86-90`, `vocabulary_screen.dart:86-90`, `spot_screen.dart:188`). Additionally, the first write is deferred through `.then` in `user_progress.dart:181-184`. Thus an exit immediately after recording can occur before even the first backend write starts, only partially addressing “**app exits shortly after an answer**” and “**Persist newest UserProgress snapshot reliably**.” Start the first queued write immediately and provide an appropriate lifecycle-safe flush strategy or document/test the durability boundary.
